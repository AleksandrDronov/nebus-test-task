# Notes SPA Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Two-page Nuxt SPA for notes with hand-rolled persistence, operation-based undo/redo, draft recovery, and accessible confirmation modals.

**Architecture:** Pinia owns persisted notes. `useNoteEditor` owns the draft. `createHistoryManager` stores operation deltas (max 50), never full note snapshots. Drafts live in a separate versioned localStorage payload and are never auto-restored.

**Tech Stack:** Nuxt 4, Vue 3 `<script setup lang="ts">`, TypeScript strict, Pinia, SCSS, Vitest, Docker.

## Global Constraints

- Nuxt.js 3/4, Vue 3 Composition API, TypeScript `strict`, no `any`
- Pinia; no `pinia-plugin-persistedstate`
- SCSS/SASS; no UI component libraries
- Undo/redo implemented by hand; no history libraries
- History stores operations/patches, not 50 full note snapshots; limit 50
- SPA: `ssr: false`
- Confirmation via custom modal only; no `alert()` / `confirm()`
- Vitest for history and store; no component tests required
- Docker + docker-compose must run the app
- Empty title blocks save; empty todos are stripped on save
- Missing note URL shows not-found state, no crash
- Native Ctrl/Cmd+Z inside inputs must not be intercepted
